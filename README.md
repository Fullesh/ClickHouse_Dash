# ClickHouse Cluster Control Plane & Chaos Engineering Dashboard

Интерактивная платформа управления, визуализации топологии и тестирования отказоустойчивости (Chaos Engineering) распределенного кластера **ClickHouse** на протоколе **Raft (ClickHouse Keeper)**.

---

## Ключевые возможности

1. **Реактивная топология кластера:**
   * Фоновый опрос узлов на пуле горутин с параллельной синхронизацией (`sync.WaitGroup`, `sync.RWMutex`).
   * Честная протокольная проверка:
     * **ClickHouse Keeper:** 4-буквенный протокол `ruok` $\rightarrow$ `imok`.
     * **ClickHouse Replicas:** бинарный нативный протокол TCP (`clickhouse-go/v2`).
   * Замер сетевой задержки (RTT Latency) в реальном времени.
   * Динамическая отрисовка соединений между серверами на SVG (координация Raft + репликация данных).

2. **Инъекция инфраструктурных сбоев (Chaos Engineering):**
   * **Сетевая изоляция Keeper (Split-Brain):** остановка сокета 9181, нарушение кворума Raft, перевод таблиц `ReplicatedMergeTree` в аварийный режим `readonly`.
   * **Авария реплики (Hard Crash / SIGKILL):** мгновенный отстрел процесса ноды 2, проверка Multi-Master zero-downtime и догоняющей синхронизации через `system.replication_queue`.
   * **Серый отказ ядра (Gray Failure / SIGSTOP):** заморозка потоков ноды 1 без закрытия сокета в ядре Linux. Моделирование дедлоков/зависаний ввода-вывода и отработка клиентских `i/o timeout`.

3. **Автоматический Day-0 Provisioning & Deprovisioning:**
   * Добавление нового узла в кластер «в один клик».
   * Генерация изолированных каталогов, макросов репликации (`macros.xml`) и production-конфигурации ClickHouse.
   * Физический запуск и остановка демонов СУБД с безопасной очисткой файловой системы.

4. **Интерфейс оператора:**
   * Строгий промышленный дизайн в стиле серверных стоек (Rack Units).
   * Без внешних тяжелых UI-фреймворков (Vanilla HTML5 / SVG / CSS).
   * Детальный технический разбор каждого инцидента прямо в модальных окнах.

## Архитектура решения

```
                             +-------------------------+
                             |   ClickHouse Keeper     |
                             |   (Raft, TCP 9181)      |
                             +------------+------------+
                                          |
                      Raft Coordination   |   Metadata Sync
                                          v
             +----------------------------+----------------------------+
             |                                                         |
             v                                                         v
+-------------------------+      Data Replication (9009)      +-------------------------+
|   ClickHouse Node 1     |<=================================>|   ClickHouse Node 2     |
|   (Native TCP 9000)     |                                   |   (Native TCP 9001)     |
+-------------------------+                                   +-------------------------+
             ^                                                         ^
             |                 Binary Protocol Pings                   |
             +----------------------------+----------------------------+
                                          |
                             +------------+------------+
                             |      Go Control Plane   |
                             |      (HTTP :8080)       |
                             +-------------------------+
```

## Быстрый старт

### Требования
* Go 1.21+

### Запуск в Docker Compose

Все компоненты (Keeper, две ноды ClickHouse и сервис Control Plane) упакованы в мультиконтейнерный стек:

```bash
docker compose up -d
```

Сервис автоматически поднимет окружение и будет доступен на порту `http://localhost:8080`.

## REST API Спецификация

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/api/v1/topology` | Получение списка всех узлов, ролей, статусов (`HEALTHY`, `WARNING`, `DEAD`) и сетевой задержки |
| `POST` | `/api/v1/chaos/trigger?action={action}` | Вызов аварии: `isolate-keeper`, `restore-keeper`, `kill-node2`, `restore-node2`, `freeze-node1`, `unfreeze-node1` |
| `POST` | `/api/v1/nodes/provision` | Динамический запуск новой ноды в кластере (принимает `id`, `host`, `port`, `role`, `shardNumber`) |
| `POST` | `/api/v1/nodes/delete?id={id}` | Остановка демона и удаление узла из топологии |
